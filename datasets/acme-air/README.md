# Acme Air Dataset

This directory contains the monolithic dataset and adapter for **Acme Air**, an IBM reference application for microservices/monolith evaluation.

The original application is tracked as a Git submodule in the `acmeair/` directory.

## Structure & Architecture
- `acmeair/`: Git submodule containing the Acme Air monolithic source code. While Acme Air is built into a single monolithic `.war` deployment, its codebase is split into multiple Gradle submodules (`acmeair-services`, `acmeair-webapp`, etc.).
- `create_unified.py`: A helper script that merges all the Java source code from the various Gradle submodules into a single, flat Eclipse Java Project named `acmeair-unified`.
- `acmeair-unified/`: The unified Eclipse project generated by the helper script. 
- `dataset.py`: Python script utilizing `javalang` to traverse the `acmeair` source code, extract all class/method signatures, and locate the required `acmeair_kdm.xmi`. It outputs this structured data to `dataset.json`.
- `acmeair_kdm.xmi`: The KDM Code Model XMI generated by Eclipse MoDisco (must be generated manually).

## Eclipse MoDisco Limitation (Why `create_unified.py` exists)
Decomposition tools (like MAGNET) require a complete **Call Graph** of the entire monolithic system. We use Eclipse MoDisco to generate this call graph as an XMI file.

However, MoDisco's "Discover KDM Code and Build Models from Java Project" feature expects a traditional, flat Eclipse Java Project structure. It struggles to generate a unified AST across modern Gradle multi-module boundaries. 

To bypass this limitation, we run `create_unified.py` to copy all the `src/main/java` folders from the submodules into a single dummy Java project (`acmeair-unified`). Importing this unified folder into Eclipse allows MoDisco to flawlessly generate a single, comprehensive `acmeair_kdm.xmi` for the entire monolith.

## Usage

**1. Create Unified Project:**
```bash
uv run create_unified.py
```
*Then, import `acmeair-unified` into Eclipse, run MoDisco to generate the Code Model, and place it at `datasets/acme-air/acmeair-unified_kdm.xmi`.*

**2. Extract Dataset Universal JSON:**
```bash
uv run dataset.py
```

## Building and Running

**1. Build the Monolithic WebApp:**
To compile Acme Air and generate the deployable `.war` archive, run the following Gradle command inside the submodule:
```bash
cd acmeair
./gradlew :acmeair-webapp:build -Pservice=morphia
cd ..
```

**2. Note on Code Fixes:**
The original Acme Air codebase expects to be deployed to WebSphere Liberty. However, it had a bug in `RESTCookieSessionFilter.java` where it eagerly looked up the `CustomerService` during the filter's instantiation phase. Because the CDI `BeanManager` is not fully bound to JNDI during Liberty's early startup phase, this caused a `NullPointerException` wrapped in an `InjectionException`. 
We modified `RESTCookieSessionFilter.java` to lazily instantiate the services upon the first `doFilter` request, ensuring Liberty finishes its startup sequence cleanly.

**3. Run via Docker Compose (with Mono2Micro):**
To launch Acme Air with MongoDB and an injected Mono2Micro Minerva agent, use the provided Docker Compose configuration:
```bash
docker-compose up --build
```
Once the Liberty server indicates it is ready, initialize the database by navigating to `http://localhost:9080/loader.html` and clicking "Load the Database". After that, you can log in on the main page.
