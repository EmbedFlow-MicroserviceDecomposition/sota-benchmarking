# JPetStore Dataset

This directory contains the monolithic dataset and adapter for **JPetStore**, a well-known sample web application built by the MyBatis community.

The original monolithic application is tracked as a Git submodule in the `jpetstore-6/` directory.

## Structure
- `jpetstore-6/`: Git submodule containing the monolithic source code.
- `dataset.py`: Python script utilizing `javalang` to traverse the Java source code, extract all class/method signatures, and locate the required `jpetstore-6_kdm.xmi`. It outputs this structured data to `dataset.json`.
- `jpetstore-6_kdm.xmi`: The KDM Code Model XMI generated by Eclipse MoDisco.

## Eclipse MoDisco Generation
Although JPetStore is compatible with modern Java versions and builds natively on modern JDKs (unlike older legacy applications), Eclipse MoDisco's 1-step KDM Discoverer is still prone to memory overload and `DanglingHREFException` on applications of this size.

To safely generate the Call Graph XMI required by decomposition tools:
1. Open Eclipse and navigate to **File > Import > Maven > Existing Maven Projects**.
2. Select the `datasets/jpetstore/jpetstore-6` directory and import it. Wait for Maven to resolve all dependencies.
3. Ensure the project shows 0 compilation errors.
4. **Manual 2-Step Generation:**
   - Right-click the `jpetstore-6` project > **Discovery > Discoverers > Discover Java Model from Java project**.
   - Right-click the resulting `jpetstore-6_java.xmi` > **Discovery > Discoverers > Discover KDM Model from Java Model**.
5. Export or rename the final XMI file to `jpetstore-6_kdm.xmi` and place it in this directory (`datasets/jpetstore/`).

## Usage

Run the adapter script using `uv`:

```bash
uv run dataset.py
```

This will parse all Java files inside the `jpetstore-6` repository and output the standardized `dataset.json` file.
