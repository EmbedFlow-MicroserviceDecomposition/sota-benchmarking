# DayTrader Dataset

This directory contains the monolithic dataset and adapter for **DayTrader**, an IBM WebSphere performance benchmark sample that simulates an online stock trading system.

The original monolithic application is tracked as a Git submodule in the `sample.daytrader7/` directory.

## Structure
- `sample.daytrader7/`: Git submodule containing the multi-module Maven source code.
- `create_unified.py`: Python script that flattens all the Java submodules into a single `daytrader-unified` directory. This is strictly required for Eclipse MoDisco to correctly resolve cross-module method calls.
- `dataset.py`: Python script utilizing `javalang` to traverse the `daytrader-unified` source code, extract all class/method signatures, and locate the required `daytrader-unified_kdm.xmi`. It outputs this structured data to `dataset.json`.
- `daytrader-unified_kdm.xmi`: The KDM Code Model XMI generated by Eclipse MoDisco (must be generated manually).

## Eclipse MoDisco Generation

Like Acme Air, DayTrader is split into multiple Maven submodules (e.g., `daytrader-ee7-ejb`, `daytrader-ee7-web`). Eclipse MoDisco struggles to resolve method references across multiple fragmented Eclipse projects. To fix this, you must unify the codebase before generating the XMI.

### 1. Unify the Codebase
Run the unification script using `uv`:
```bash
uv run create_unified.py
```
This will automatically extract all `.java` files from the submodules and generate a clean, flat Eclipse project in a new `daytrader-unified` directory.

### 2. Import into Eclipse
1. Open Eclipse and navigate to **File > Import > General > Existing Projects into Workspace**.
2. Select the newly created `datasets/daytrader/daytrader-unified` directory.
3. Eclipse will immediately recognize it as a Java project thanks to the `.project` and `.classpath` files generated by the script.

### 3. Generate the Call Graph
*Note: Because this is a massive Java EE application, the MoDisco ATL engine may crash on missing `javax` dependencies. Use the standard legacy workarounds.*
1. In **Window > Preferences > MoDisco > Java > Discoverer**, ensure you CHECK **Deep analysis**, **Serialize all elements**, and crucially **Ignore unresolved bindings**.
2. Right-click `daytrader-unified` > **Discovery > Discoverers > Discover Java Model from Java project**.
3. Right-click the resulting `daytrader-unified_java.xmi` > **Discovery > Discoverers > Discover KDM Model from Java Model**.
4. Rename the output to `daytrader-unified_kdm.xmi` and place it in this directory (`datasets/daytrader/`).

## Usage

Once the `daytrader-unified_kdm.xmi` is in place, run the adapter script:

```bash
uv run dataset.py
```

This will parse the unified directory and output the standardized `dataset.json` file for the evaluation pipeline.
