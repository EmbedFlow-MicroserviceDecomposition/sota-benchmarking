# JForum Dataset

This directory contains the monolithic dataset and adapter for **JForum**, a popular Java-based discussion board system.

The original monolithic application is tracked as a Git submodule in the `jakartaEE/` directory (from the `jforum/jakartaEE` repository).

## Structure
- `jakartaEE/`: Git submodule containing the monolithic source code.
- `dataset.py`: Python script utilizing `javalang` to traverse the Java source code, extract all class/method signatures, and locate the required `jforum_kdm.xmi`. It outputs this structured data to `dataset.json`.

## Eclipse MoDisco Generation (FAILED)

**Warning:** Eclipse MoDisco is completely incapable of generating the KDM Code Model (`_kdm.xmi`) for this specific codebase, regardless of the workarounds applied. 

While the intermediate Java Model (`jforum2_java.xmi`) can be generated by MoDisco, the ATL engine (`javaToKdm`) permanently crashes with `VMException: Cannot convert javaToKdm` during the transformation phase.

### Attempted Workarounds (None Succeeded):
1. **Standard Generation:** Importing as a standard Maven project and running the 1-step or 2-step Discoverer results in an ATL crash due to unresolved bindings from complex legacy JSP and Servlet dependencies.
2. **Ignore Unresolved Bindings:** Even with "Ignore unresolved bindings" checked in MoDisco Preferences, the AST is too fragmented for the ATL script.
3. **Project Simplification:** Ripping out all Maven configurations and dependencies to create a "bare-minimum" Eclipse Java project containing strictly the `.java` files still triggers the exact same ATL crash on the unresolved AST nodes.

### Conclusion for JForum
Because MoDisco cannot process the source code into KDM, decomposition tools that strictly rely on MoDisco's KDM schema (like MAGNET) cannot natively evaluate the JForum dataset. Any evaluation of JForum requires an alternative Call Graph generator (such as Java2KDM or a custom AST parser) to artificially synthesize the `jforum_kdm.xmi`.

## Usage

You can still run the adapter script to extract the method dataset via `javalang`:

```bash
uv run dataset.py
```

This will parse the raw Java files and output `dataset.json`, which can be used by tools that do not require KDM input.
