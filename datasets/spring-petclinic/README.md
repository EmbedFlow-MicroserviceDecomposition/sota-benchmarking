# Spring PetClinic Dataset

This directory contains the monolithic dataset and adapter for **Spring PetClinic**, a highly popular sample application demonstrating the Spring framework.

The original monolithic application is tracked as a Git submodule in the `spring-petclinic/` directory.

## Structure
- `spring-petclinic/`: Git submodule containing the Spring PetClinic monolithic source code.
- `dataset.py`: Python script utilizing `javalang` to traverse the `spring-petclinic` source code, extract all class/method signatures, and locate the required `spring-petclinic_kdm.xmi`. It outputs this structured data to `dataset.json`.
- `spring-petclinic_kdm.xmi`: The KDM Code Model XMI generated by Eclipse MoDisco (must be generated manually).

## Eclipse MoDisco Generation (Workarounds)
Spring PetClinic is a straightforward, single-module Maven project. However, the latest versions use modern Java (17/21) which Eclipse MoDisco's outdated JDT parser cannot handle. 

To successfully generate the Call Graph XMI without triggering a `DanglingHREFException`, you **must** follow these precise steps to evaluate a Java 8 compatible version:

### 1. Checkout the Java 8 Version (`1.5.x` tag)
Inside the `spring-petclinic` submodule, checkout the `1.5.x` tag:
```bash
cd spring-petclinic
git checkout 1.5.x
```

### 2. Remove the `wro4j-maven-plugin`
The `wro4j-maven-plugin` is used for frontend LESS/CSS optimization, but it crashes on modern Java setups. Since we only care about Java source code for the call graph, open `spring-petclinic/pom.xml` and **delete** the entire `<plugin>` block for `ro.isdc.wro4j`.

### 3. Build with Java 1.8
Ensure your terminal is using Java 1.8 (e.g., via `sdk use java 8.0.412-tem`) and run:
```bash
./mvnw clean install -DskipTests
```

### 4. Configure Eclipse
1. Open Eclipse and navigate to **File > Import > Maven > Existing Maven Projects**.
2. Import the `datasets/spring-petclinic/spring-petclinic` directory.
3. Ensure the project is using Java 1.8 (Right-click project > **Properties > Java Build Path > JRE System Library**).
4. Right-click the project > **Maven > Update Project**. Ensure there are **0 compilation errors**.

### 5. Manual 2-Step XMI Generation
Running the KDM discoverer directly often causes out-of-memory or `DanglingHREFException` crashes on this dataset. Bypass this by running it in two explicit stages:
1. Right-click the `spring-petclinic` project > **Discovery > Discoverers > Discover Java Model from Java project**. (This creates `spring-petclinic_java.xmi`).
2. Right-click the newly generated `spring-petclinic_java.xmi` > **Discovery > Discoverers > Discover KDM Model from Java Model**.
3. Rename the final KDM output to `spring-petclinic_kdm.xmi` and place it in this directory (`datasets/spring-petclinic/`).

## Usage

Once the `spring-petclinic_kdm.xmi` is in place, run the adapter script using `uv`:

```bash
uv run dataset.py
```

This will parse all Java files inside the repository and output the standardized `dataset.json` file.
