# Apache Roller Dataset

This directory contains the monoli (Did not work)thic dataset and adapter for **Apache Roller**, a classic open-source Java blog server used to drive large multi-user blogging sites.

The original monolithic application is tracked as a Git submodule in the `roller/` directory.

## Structure
- `roller/`: Git submodule containing the multi-module Maven source code.
- `create_unified.py`: Python script that flattens all the Java submodules into a single `roller-unified` directory. This is strictly required for Eclipse MoDisco to correctly resolve cross-module method calls (just like Acme Air and DayTrader).
- `dataset.py`: Python script utilizing `javalang` to traverse the `roller-unified` source code, extract all class/method signatures, and locate the required `roller-unified_kdm.xmi`. It outputs this structured data to `dataset.json`.

## Eclipse MoDisco Generation (FAILED)

Because Apache Roller is split into multiple Maven submodules (e.g., `app`, `planet-business`, `planet-web`), Eclipse MoDisco will fail to resolve cross-module method invocations if you import it directly as a Maven project. You must unify the codebase first.

### 1. Unify the Codebase
Run the unification script using `uv`:
```bash
uv run create_unified.py
```
This will automatically extract all `.java` files from all submodules and generate a clean, flat Eclipse project in a new `roller-unified` directory.

### 2. Import into Eclipse
1. Open Eclipse and navigate to **File > Import > General > Existing Projects into Workspace**.
2. Select the newly created `datasets/apache-roller/roller-unified` directory.
3. Eclipse will immediately recognize it as a Java project thanks to the `.project` and `.classpath` files generated by the script.

### 3. Generate the Call Graph
*Note: Depending on your Eclipse workspace configuration and the sheer size of the Apache Roller codebase, you may encounter the standard MoDisco memory limits.*
1. In **Window > Preferences > MoDisco > Java > Discoverer**, ensure you CHECK **Deep analysis**, **Serialize all elements**, and **Ignore unresolved bindings**.
2. **Manual 2-Step Generation:**
   - Right-click `roller-unified` > **Discovery > Discoverers > Discover Java Model from Java project**.
   - Right-click the resulting `roller-unified_java.xmi` > **Discovery > Discoverers > Discover KDM Model from Java Model**.
3. Rename the output to `roller-unified_kdm.xmi` and place it in this directory (`datasets/apache-roller/`).

## Usage

Once the `roller-unified_kdm.xmi` is in place, run the adapter script:
```bash
uv run dataset.py
```
This will parse the unified directory and output the standardized `dataset.json` file for the evaluation pipeline.

### Mono2Micro Integration and Docker Execution

The `roller` submodule provides native Docker support, but to successfully deploy it and run the Mono2Micro Minerva agent, several modifications must be made to the Docker configurations.

**1. Modify the `Dockerfile`:**
- **Local Build Source:** The original Dockerfile clones the code from GitHub, bypassing your local source. Modify the build stage to copy the local directory instead:
  ```dockerfile
  # Remove: RUN git clone https://github.com/apache/roller.git
  # Remove: RUN git checkout tags/roller-6.1.0; \
  COPY . /tmp/roller
  RUN mvn -Duser.home=/builder/home -DskipTests=true -B clean install
  ```
- **PostgreSQL Port Fix:** Change `ARG DATABASE_HOST=postgresql:5434` to `ARG DATABASE_HOST=postgresql:5432` to match the default port exposed in `docker-compose.yml`.
- **JDK Bug Fix:** The original base image `tomcat:9-jdk17-openjdk-slim` contains an ancient Java 17 build with a fatal `cgroup v2` bug that crashes Tomcat during initialization. Change the base image to `tomcat:9.0-jdk17-temurin-jammy`.

**2. Optimize Docker Cache (Optional):**
To prevent Docker from downloading Maven dependencies on every build, add a `.dockerignore` file in the `roller/` directory:
```text
docker-compose.yml
.git
.github
target/
app/target/
**/*.war
**/*.jar
docker/roller-data/
```
*Tip: You can also use `--mount=type=cache,target=/builder/home/.m2` in the `RUN mvn` command to cache Maven dependencies across builds.*

**3. Modify `docker-compose.yml` (Inject Minerva):**
To trace the application, map the Minerva tools into the Tomcat container and append the JVM arguments. Add the following to the `roller` service:
```yaml
      volumes:
         # ... existing volumes ...
         - ../../../tools/mono2micro/Mono2Micro-CLI/instrumenter:/minerva:ro
         - ../../../tools/mono2micro/outputs/apache-roller/tables:/tables:rw
      environment:
         - JAVA_OPTS=-javaagent:/minerva/minerva-agent-1.0.jar=/tables
```

**4. Build and Start Roller:**
```bash
cd roller
docker-compose up --build
```

**5. Extract Runtime Traces:**
Mono2Micro's `usecase` tool requires you to capture the real-time standard error output from the container. In a new terminal window, pipe the container logs into the output directory:
```bash
docker logs -f roller-roller-1 > ../../../tools/mono2micro/outputs/apache-roller/logs/console.log 2>&1
```

**6. Record Use Cases:**
In a third terminal, run the orchestrator's `usecase` CLI:
```bash
../../../tools/mono2micro/Mono2Micro-CLI/mono2micro usecase -o ../../../tools/mono2micro/outputs/apache-roller/contexts/usecases.json
```
