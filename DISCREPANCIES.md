# fyp-benchmarking vs sota-benchmarking: discrepancies found during the migration

`fyp-benchmarking` is retired and `sota-benchmarking` is the only repository. This lists where the two disagreed, what was
decided (`sota-benchmarking` wins unless noted), and what changed as a result. Each item was observed in the code or measured,
not assumed. "fyp" = `fyp-benchmarking`, "sota" = this repository.

## 1. Data model

| Topic | fyp | sota (before) | Now |
| :--- | :--- | :--- | :--- |
| Partition unit | classes (`{class: cluster}`) | `dataset.json` is method-level; `output.json` could be either | Unchanged model, one resolver: method ids roll up to classes by majority vote (ties to the smallest cluster id), classes explode to all their methods (`metrics/partition.py`) |
| Resolution rules | exact FQNs | 7 copies of fuzzy matching (simple names, parent classes, `" ["` suffixes) | One implementation; unknown ids are counted (`coverage.unmatched_ids`), never guessed; a bare simple name matches only if unique; `-res` resource nodes are skipped |
| Empty microservices | not counted (K = distinct cluster ids) | counted in K | Not counted (an empty cluster would inflate CHM/CHD/IFN) |
| Error outputs | n/a | a failed tool's `output.json` could be scored | `{"error": ...}` is refused by `compute_all.py` (exit 1) |
| Class list | `nodes.csv` lists every class | classes with no methods and no edges were invisible | `dataset.json` has a top-level `classes` list |

## 2. Parser and graph

| Topic | fyp | sota (before) | Now |
| :--- | :--- | :--- | :--- |
| Parser | JavaParser + symbol solver (Java) | `javalang` (Python): callee class guessed from the qualifier text; any file it could not parse silently returned `[]` | JavaParser (`datasets/extractor/`) behind each `dataset.py`; a parse failure exits 1 and names the file |
| Edge types | CALL, EXTENDS, IMPLEMENTS, FIELD | CALL only | all four |
| Edge weight | number of call sites | always 1.0, one edge per class pair | number of occurrences |
| Source roots | `*/src/main/java` | every `.java` under the dataset (tests, docs examples, tools, the Maven wrapper) | `*/src/main/java`, else the top-level `src/` (Eclipse layout, acme-air), else the root |
| Nested classes | `pkg.Outer.Inner` | `pkg.Inner` | `pkg.Outer.Inner` (JavaParser FQN) |
| `dataset.py` | n/a | 12 copies of 143 lines, 10 of which resolved `source_path` against the cwd and 2 against the output directory | one `datasets/common.py`; `source_path` is relative to the output directory |
| Method edge fallback | n/a | SM/ICP/IFN added class **and** method edges when `dataset.json` had no edge list (double counting) | removed |

Measured on the 12 Java datasets (`javalang` vs JavaParser method ids): every javalang method is present in the new output except
test classes (e.g. 348 of Roller's 410 missing), nested-class renames, and non-production code (Roller `docs/examples`, JForum
`tools/phpbb2jforum`, JPetStore `.mvn/wrapper`). Acme Air initially produced 1 edge instead of 204 because the extractor's source
root was wrong for its Eclipse layout; fixed and covered by a test.

## 3. Metrics

Same formulas (verified numerically on a synthetic fixture generated by running fyp's `metrics.py` and CHGNN's released
`metric.py`): SM, ICP, IFN, NED (fixed and relative), CHM, CHD, BCP.

| Topic | fyp | sota (before) | Now |
| :--- | :--- | :--- | :--- |
| Layout | one `metrics/metrics.py`, `results.csv`, `MATRIX.md` | one `metric.py` per metric + `compute_all.py`, per-tool `outputs/<dataset>/` | sota layout; `results.csv`/`MATRIX.md` are not carried over |
| NED TripleBound | `NED_TripleBound` column | absent | `ned_score.json: score_triplebound` (classes in extreme partitions / #partitions, lower is better, unbounded) |
| SM, CHGNN-repo variant | `sm(undirected=True)` (equals CHGNN's own `get_structural_modularity`) | code existed but was not exposed | `sm_score.json: score_undirected` |
| IFN, CHGNN-repo variant | cross-edge IFN | absent | `ifn_score.json: score_cross_edge` (equals CHGNN's `get_IFN`) |
| BCP use cases | entrypoint reachability, FQN keys | captured while running Mono2Micro, simple-name keys, label `Unknown` | sota's `usecases.json`; `Unknown` is dropped (fyp had no such label) |
| Coverage | not reported | not reported | `coverage` block in every score file (`classes`, `assigned`, `unassigned`, `unmatched_ids`, `conflicts`) |

Effect on the existing Triplet-Guided CHGNN outputs (outputs unchanged, only the scoring inputs changed): SM moved (it now counts
EXTENDS/IMPLEMENTS/FIELD edges), ICP/IFN/CHM/CHD moved (resolved callees instead of guessed ones), NED and BCP moved where the old
output listed test classes. Examples: Spring PetClinic SM 0.024 -> 0.252, Bear Board NED 0.90 -> 0.56, Roller BCP 2.31 -> 1.56. Those
tracked scores were regenerated; the old numbers are in git history.

## 5. Methods

| Method | fyp | sota |
| :--- | :--- | :--- |
| CHGNN | conda env `CHGNN` (x86 python: **no longer runs on this machine**, `Bad CPU type in executable`) + adapter scripts; 30 inner runs per `Graph.py` call, first one used | Docker image (`linux/amd64`), `run_chgnn.py` patches `multiple_runs=30` to 1 in memory so the submodule stays clean; DayTrader and Plants use the authors' bundled inputs as in fyp (no seeds/DB map exist for our checkouts) |
| AE-K / VAE-C | `vaec_run.py` (AE-K, originally mislabelled "VAE-C") and `vaec_c_run.py`; TensorFlow 2.21 | `tools/_common/vaec_core.py`, run with `uv` and pinned inline deps; VAE-C uses the thesis's k=5 on bear-board/pharmacy/autocare |
| FoSCI | `fosci-wrap` + hand-run steps; hand-picked K per dataset | one `tool.py`; N = min(per-dataset N, atoms-2), N/A below 4 atoms; fosci-wrap vendored unmodified (the v2 release is a plain directory, not a repository) |
| CARGO | Doop facts + a locally patched `dgi`; scored against a graph rebuilt from Doop's own facts because the bundled jars do not always match any source checkout | patched copy of `dgi` (patch file, submodule pristine); scored against `dataset.json` like every other tool, so classes the Doop graph does not cover show up as `unassigned` |
| CoGCN | cloned, never run | adapter written (content features reconstructed from names), runs in Docker |

Cells that are N/A and why (each is an error-form `output.json`, not a missing file): see `tools/<tool>/README.md`.

## 6. Protocol

Unchanged from fyp: stock/default fixed-k configuration, mean over repeated unseeded runs, no k-sweep-and-select (CARGO: the
paper's K = 3..13 x 5 seeds grid, averaged). Not comparable with each paper's own published numbers (different model selection),
as fyp already documented.

## 7. Things the migration surfaced that are not fixed

- The Doop facts that CARGO consumes and the self-generated FoSCI traces come from fyp's runs (same pinned commits except where noted
  above); regenerating them needs Doop (hours per dataset, a hand-repaired Gradle/Maven toolchain) and the tracer agent plus live traffic.
- CARGO's bundled `acmeair` jar is a MongoDB variant that does not exist in `acmeair/acmeair`'s history; JPetStore and Plants jars are
  likewise untraceable. Their cells measure a different codebase than the other tools' same-named cells wherever `coverage` is low.
- The authors' FoSCI traces for JForum were recorded on their JForum 2 build; our pin is the Jakarta EE port, so some traced classes are
  `unmatched_ids`.
- Unit/regression checks exist for the new code (`tests/`), but nothing re-validates a tool's output against its paper's published numbers.

## 8. Re-run results vs fyp-benchmarking (informational)

Every cell was re-run through this repository's pipeline; nothing was carried over from `results.csv`. The table pairs fyp's
canonical row with the new mean (`tools/<tool>/outputs/<dataset>/metrics_mean.json`) for the cells that existed in both. "n" is the
number of runs (CARGO: grid entries); the last column is how many dataset classes the partition covers, which fyp did not report.
fyp's SM/ICP/IFN/NED are the canonical variants; the two repositories' numbers are not expected to match exactly (different
extractor, edge set, pins and resolver; see sections 1-4).

Difference in SM (new minus old), over the cells in the table:

| :-- | :-- | :-- | :-- |
| VAE-C | 11 | -0.001 | 11 of 11 |
| AE-K | 9 | +0.013 | 8 of 9 |
| FoSCI | 9 | +0.026 | 7 of 9 |
| CHGNN | 11 | +0.031 | 7 of 11 |
| CARGO | 10 | -0.080 | 3 of 10 |

- **FoSCI** reproduces fyp on JPetStore and Pharmacy almost exactly (ICP and IFN identical, SM 0.082 -> 0.081 and 0.095 -> 0.092).
  Those are the cells where the dataset, trace and class set are the same on both sides.
- **VAE-C and AE-K** are close to fyp wherever the dataset is the same code.
- **CHGNN** is higher on most cells. The cause was not isolated; candidates are the automatic exclusion of isolated classes, the
  different class/edge set from the JavaParser `dataset.json`, and the different pins for JPetStore, PetClinic and JForum.
- **CARGO** moves the most, and mostly downwards in SM and upwards in ICP: it is now scored against `dataset.json`, which has
  EXTENDS/IMPLEMENTS/FIELD edges and all classes, instead of the graph rebuilt from Doop's own facts. Roughly a third to a half of the
  classes are `unassigned` for most datasets (Doop only models classes it reaches), so read the coverage column before comparing.
- JavaFX-POS has a CARGO cell here (fyp had one too); CHGNN, AE-K, VAE-C and FoSCI are N/A for it, and GenApp is N/A everywhere.
- Roller's CHGNN row had n=2 in fyp (n=10 here) and FoSCI Roller is a single run in both.
